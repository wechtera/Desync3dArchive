Reconciliation

            
What it does: Confirms every file in the catalog is really on storage and intact. Offline libraries are skipped, not marked missing.

            
How: Fast checks each file exists at the right size, and only reads folder listings. Deep also tests ZIP checksums and STL headers and compares SHA-256 hashes, which reads every file on the NAS and can take a long time.

            
To validate: Discrepancies above reads 0. If not, fix what is listed and run it again until the count falls to 0.

Reverse Orphan Audit

            
What it does: Finds folders and files in the vault that the catalog does not know about. The ad-hoc folder is skipped.

            
How: Walks the vault on the NAS and looks each folder up in the catalog. It only lists what it finds. Deleting or adding one to the catalog is a separate choice in the results.

            
To validate: Open a listed folder in Finder and confirm it really is unknown. Anything you delete appears under Settings > Audit.

Buffer Sizing & Network Tradeoffs

          
    
            
  • 
              Download Stream Buffer: Smaller buffers (0.25–0.5 MB) reduce RAM consumption. Larger buffers (2–4 MB) maximize sequential write throughput on fast NVMe scratch drives.
            
    • 
            
  • 
              NAS Offload Buffer: 4 MB is optimal for 1 GbE networks (~112 MB/s). Increasing to 8–16 MB dramatically reduces protocol overhead on 2.5 GbE and 10 GbE connections.

System Architecture & Operations Guide

          

            Operational reference for storage staging, authentication pipelines, stash manifests, and catalog integrity auditing.
          

        

      

    


    

      

        

          
Quick Start & Core Workflow

        

        

          
The library lifecycle operates via decoupled, idempotent pipeline stages designed to resist upstream throttling and bot detection:

          
    
            
  1. 
              Configure Session Cookies: Under Settings → Session Authentication & Cookies, supply your PHPSESSID and cf_clearance tokens.
            
    2. 
            
  2. 
              Execute Library Scrape: Under Manage / Retrieve / Reconcile Assets → MMF Sync, click Launch Library Scraper. Playwright intercepts data API payloads and exports all model IDs to model_ids.txt.
            
    3. 
            
  3. 
              Ingest Model Metadata: Click Open Metadata Ingestion Pipeline. The worker computes an incremental delta, populating models, tags, and files, and caching cover previews locally.
            
    4. 
            
  4. 
              Staged Downloads & Offload: Select models from the Pending & Queue Explorer tab to queue them for fast NVMe chunk downloads and automatic migration to your vault.
            
    5. 
          

        

      


      

        

          
Two-Tier Staging & NAS Offload Architecture

        

        

          
To eliminate network file protocol lockups and protect mechanical parity arrays, storage follows a dual-tier staging pipeline:

          

            Tier 1: High-Speed NVMe Scratch (Staging Path)

            All parallel chunk downloads, temporary streams, and archive extraction passes execute inside the local scratch folder.
          

          

            Tier 2: Cold/Archive Target Storage Pool (NAS Vault Path)

            Once all files for a model are downloaded and validated against expected archive signatures, a background offloader migrates the clean directory tree directly into the destination library path.
          

          
    
            
  • Zero Partial Files: The destination storage directory never holds corrupted or incomplete downloads.
    • 
            
  • Concurrency Isolation: Parallel transfers will not choke single-threaded network protocols or trigger disk thrashing.
    •

Circuit Breaker & Unavailable Objects (Tombstones)

        

        

          
The ingestion and download engines employ proactive safeguards to prevent IP bans and avoid infinite retry loops:

          
    
            
  • 
              Rate Limiting (HTTP 429): The worker inspects the Retry-After header, logs the hold period, and sleeps execution until the window elapses.
            
    • 
            
  • 
              Circuit Breaker Pause (HTTP 401/403): If session credentials expire mid-transfer, downloads halt immediately and activate the warning banner.
            
    • 
            
  • 
              Tombstone Recording (HTTP 404 / 410): Models removed or privatized by creators return 404 and are safely cataloged as unavailable without breaking ingestion runs.
            
    • 
          

        

      


      

        

          
Stash Management (“A pile of gray”)

        

        

          

            Stashes serve as logical staging manifests for curating printing campaigns, resin batches, or build queues before transferring files across networks.
          

          

            Absolute File Safety Guarantee:

            All stash actions are purely logical manifest operations in SQLite. Adding or deleting items will never touch physical archive files on disk.
          

        

      


      

        

          
Configuring the Server: production.env

        

        

          
Settings live in two places. Anything you can change in the Settings tab is stored by the app. Server settings, which have to be known before the app can start, live in ~/.config/desync-archival/production.env. Settings > Directories shows the exact path on this machine, and every other location the app uses.

          
    
            
  • Changes apply on restart. Save the file, then run scripts/server.sh restart.
    • 
            
  • It is a shell file. Write NAME=value with no spaces around the equals sign, and put quotes around a path containing spaces.
    • 
            
  • Passwords and keys don't go here. They belong in the secrets file, set from Settings or dbtool set-password.
    • 
            
  • Development is separate. A development run reads .env in the checkout, and is refused any path in DESYNC_PROTECTED_PATHS.
    •
